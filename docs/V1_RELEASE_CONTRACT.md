# v1 candidate qualification contract

The target is a reliable Rust-native bounded reasoning and learning system.
This is a qualification plan, not a declaration that the candidate is ready.
The existing [release gates](STABLE_RELEASE_GATES.md) and historical results
remain authoritative. A version number cannot convert a failed research
criterion into a successful one.

| Gate | Required evidence before claiming it |
| --- | --- |
| Independent runtime | A configured process drives the cognitive cycle with two authorized endpoints, local evaluation, persistent learning and reciprocal offers without an LLM |
| Exact reasoning | Existing unchanged BRUTE parity plus graph conditional-certificate, contradiction, abstention and query-prior isolation tests |
| Persistent adaptation | Fresh exact promotion/evaluation anchors, retained nonempty predictions after actual restart, durable policy changes and counterexample revocation |
| Controlled topology | Three private native owners, actual per-edge authenticated exchanges, custody bindings, receiver-side consent/revocation and aggregate resource accounting |
| Bounded exploration | Actual prospective choices change because of durable prior outcomes; neutral-history and matched-budget controls expose alternative explanations |
| Durable compatibility | Legacy records remain byte-identical; explicit new-feature migration, interruption protection, owner validation, backup and restore retain the full supported state |
| Local duration | One source-frozen, once-only 60-minute campaign with actual live-listener spans and independently verified raw timing/lifecycle evidence |
| Adversarial envelope | Wrong grammar, conflicting evidence, changed schemas, denied identities, lost acknowledgements, resource exhaustion and stale/corrupt state fail explicitly |
| Rust embedding | Documented public APIs, schema versions, supported bounds and a declared compiler/platform test window |
| Public delivery | All required source/platform checks, immutable tag, exact bundle/checksum sets and actual installed public-binary execution |

Every completed or failed item must point to its raw receipts and exact source.
Engineering checks, individual learning changes, experimental utility and
deployment qualification have separate statuses. Repeated cycles and remapped
copies are not independent scientific samples.

## Research conclusions remain independent

The new query-policy transfer protocol is frozen before opening targets. Its
strong reciprocal-utility criterion is evaluated against complete matched
controls. If those controls remove the gain, the result is
`NOT_DEMONSTRATED`, even when software operation and persistent learning pass.
The same rule applies to the three-agent topology's measured cost losses.
Neither outcome permits a performance-breakthrough claim.

The v0.5 primary remains HOLD. Its engineering reproduction and later protocols
do not replace it. Original algorithms, evidence, registrations and failure
records remain accessible through pinned source and release archives.

## Crosswalk to the original roadmap

This contract does not replace the original version objectives. Each result
below must be updated from the actual completed receipt, including failures.

| Original objective | Current evidence or outstanding criterion |
| --- | --- |
| v0.1–v0.3 foundation, exchange, adaptive memory | Published bounded native learning, exact parity, private owner histories, restart, migration and rollback evidence; later format changes need new compatibility checks |
| v0.4 reciprocal improvement | Conditional affine and graph benefits in the published declared cost models; cheap-observation and matched-budget controls limit the interpretation |
| v0.5 adaptive relationships | Primary remains HOLD; engineering reproduction completed the same worlds; scores changed without changed actions and fixed-peer selection was cheaper; better unfamiliar-partner selection remains unachieved |
| v0.6 transferable knowledge | New exact policy representation and retention checks implemented; prospective matched-control utility result is pending; `NOT_DEMONSTRATED` leaves the strong gain criterion unachieved |
| v0.7 controlled topology | Three-peer native implementation and focused consent/custody tests; full source-frozen evidence is pending; negative aggregate utility is reported as a loss |
| v0.8 bounded exploration | Native outcome-conditioned choice and restart control implemented; equality with the observation-budget control does not establish greater acquisition efficiency |
| v0.9 stability and generalization | Adversarial regression envelope implemented; new duration qualification pending; generalization beyond the declared finite families remains unverified |
| v1.0 stable bounded software | Requires the operational gates above, published compatibility limits and verified delivery; it does not close unmet research criteria by renaming them |

The two-host gate stays open because evidence is unavailable. Restricting the
support contract to the tested PC is a release-scope decision, not deployment
evidence. Duration qualification, scientific utility and public delivery must each
retain their own result.

## Supported scope must match the qualification

The current authorized deployment is this PC. A local release can claim only
the tested bounded modes. Independent two-host operation remains
`OPEN_UNAVAILABLE`, with no implication that same-host TLS or remote CI runners
closed it. Multi-host availability, arbitrary new task families, unattended
credential issuance/renewal, general intelligence and autonomous self-improvement
remain unverified unless separately supported by new evidence.
