# Evidence-gated evolution

These are version objectives, not automatic capability promises. Later-feature
prototypes in Genesis do not justify skipping the associated research gates.
Maintain failed criteria and matched-cost controls for every release.

| Version | Objective | Required next evidence |
| --- | --- | --- |
| v0.1 Genesis | Clean BRUTE derivative; native exact reasoning; authorized telemetry; independent vertical slice | Delivered local finite-domain loop, exact parity, persistence, rollback, reciprocal strategy acceptance and honest controls |
| v0.2 First Symbiosis | Two-way structured exchange | Independently implemented partners and held-out tasks; useful unsolicited contributions; no teacher-table leakage; matched-cost controls |
| v0.3 Adaptive Memory | Durable versioned learning with rollback | Broader task representations, crash/recovery campaigns, independent evaluation isolation and migration compatibility |
| v0.4 Reciprocal Improvement | Benefits to both systems | Paired repeated experiments against isolated adaptive learners; include all costs and regressions; no repeated-case inflation |
| v0.5 Adaptive Relationships | Select useful partners | Prospectively predict usefulness from telemetry and validate selection on unseen partners; similarity is insufficient |
| v0.5.1 Durable Operations | Maintain the bounded software core | S5 local PASS; two-host operation, duration reliability and later research criteria remain open |
| v0.6 Transferable Knowledge | Reuse abstractions | Unfamiliar tasks, channel/action remapping, negative transfer, wrong-family controls and persistent held-out gains |
| v0.7 Symbiotic Networks | Controlled topology | Consent per edge, bounded aggregate budgets, network failures and independently tracked individual benefits |
| v0.8 Self-Directed Exploration | Select experiments within limits | Audited experiment choice, information gain vs cost, cancellation, independent approval boundaries and no unsanctioned attachment |
| v0.9 Generalization and Stability | Adversarial and drift stress | Wrong/malicious knowledge, dishonest APIs, long-running stability, drift, resource exhaustion and recovery |
| v1.0 Stable SYMBIOTE | Reliable embeddable Rust system | Secure nonlocal transports, reproducible reciprocal learning across multiple independent controlled environments, compatibility and documented failure envelope |

The v0.2 implementation now exercises two different native learning algorithms,
exact active queries, held-out inputs and reciprocal verified evidence reuse.
Its trusted local oracle and declared cost model are explicit limitations; both
learners still share one controller process. See [v0.2 research](RESEARCH_V02.md).

v0.3 adds two supervised native peer processes, private retained knowledge,
byte-preserving migration and explicit crash recovery. Its TLS transport is
tested separately as a library; the process experiment still uses authorized
loopback v1. Graph reasoning is a verified primitive, with operational graph
learning still pending. See [deployment evidence](../experiments/v0.3/deployed-verification.json).

v0.4 turns route planning into a second persistent exchange task and integrates
TLS into the supervised affine runtime. The complete graph cohort includes
beneficial and harmful exchanges, withheld partial maps and actual offline replay.
See [v0.4 methods and results](RESEARCH_V04.md). Those results are conditional on
one topology and a fixed pair; they do not automatically satisfy later gates.

v0.5 implements the prospective relationship policy, configured native knowledge
service and exact empty-setup restoration. Its first primary remains HOLD after
port exhaustion. The repaired engineering reproduction completes all 192 cases
on the same 24 unfamiliar graphs and demonstrates retained knowledge in two
contexts. The fixed-peer control remains cheaper; learned scores change without
changing selected actions. Unseen-partner generalization and a better-selection
claim remain open. See [v0.5 findings](RESEARCH_V05.md).

v0.5.1 adds reviewed offline policy/certificate lifecycle and verified owner-state
backup/restore. Its default gate passes 292 Rust test executions, 53 Python tests
and 6,093 parity cases. A separately executed ignored test passes a fixed
24-cycle local TLS continuity campaign with two owners and two retained models.
It includes reviewed two-leaf rotation, denial/regrant, an actual service crash,
a lost quarantine reply and midpoint relocation. The 16 named regressions are
repeats; the two fixed fixtures add no new scientific samples. S3 and S4 checker
HOLDs remain preserved. [Local qualification](LOCAL_QUALIFICATION_V051.md) and
[evidence](../experiments/v0.5.1/README.md) record the exact boundaries.

The public v0.5.1 assets now pass download/checksum and architecture checks; the
Windows binary passes online installation, restart and verified backup/restore.
The next operational work is a predeclared longer-duration local campaign.
Independent two-host deployment remains `OPEN_UNAVAILABLE`; the accepted scope
is this PC. Stable v1.0
also needs its broader scientific criteria, compatibility window and documented
failure envelope. No v0.6 research milestone is inferred from maintenance tests.

The next research milestone needs newly declared transfer tasks and unfamiliar
partner identities, including negative transfer and matched-cost controls.
[Protocol 002](RESEARCH_V06_PROTOCOL.md) freezes that evaluation and has not
been opened. Do not retune the completed query-policy cohort. The value
function and reciprocal receipt are mechanism code. On the enumerated width-3
affine family they decline a hint that ties the fixed basis after costs. A
content digest cannot verify benefit; a completed receiver promotion can, and
only when the value plan sent the payload. That attribution check is not
protocol 002 and does not convert protocol 001 from `NOT_DEMONSTRATED`. The [stable release gates](STABLE_RELEASE_GATES.md)
distinguish reliable bounded software from unresolved hypotheses.

A proposed single-PC v0.6 pilot should test a portable reasoning strategy on
held-out graph topologies, unfamiliar partners and remapped action labels. Compare
complete costs and held-out coverage against no-transfer and equal-budget fresh
learning, with zero incorrect certificates. Report each participant's gains and
losses separately; require nonempty retained predictions after real restarts
with zero replay oracle calls. Wrong-family offers and drift must be rejected or
revoked without deleting history. Freeze the actual cohort and criteria before
execution. Missing evidence or exceeded limits is HOLD; absent controlled gains
is NOT_DEMONSTRATED. This proposal does not close the two-host or stability gates.
