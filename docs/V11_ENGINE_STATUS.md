## Remaining release gates

1. Freeze clean source/version/lock/toolchain after the combined software,
   documentation, compatibility and independent-consumer checks pass.
2. Run the once-only [registered transfer protocol](V11_TRANSFER_PROTOCOL_001.md):
   both owners independently acquire useful knowledge; exact transfer is
   independently evaluated; actual interruption/recovery precedes fresh use;
   outcomes reconcile once after restart. Optimized isolation, cache and
   equal-resource controls remain separate.
3. Build the four staged platform images; execute their installed lifecycle and
   external consumer; run the explicitly opted-in disposable Linux ENOSPC gate;
   independently verify signed build origin and dependency inventories.
4. Qualify the **actual staged Windows image** in a fresh 60-minute/120-cycle
   campaign with restarts and declared recovery events. Independently review
   preserved evidence. Earlier hours do not satisfy this gate.
5. Stage immutable bytes and sanitized evidence. Publish provisionally without
   changing the previous stable latest release. Anonymously retrieve and accept
   the delivered bytes on each claimed architecture before stable promotion.

No step may manufacture completed work, replace an existing asset, move a tag,
silently raise a study budget or relabel unknown economics as measured gain.
Failure is preserved with an explicit result and next action.

## Supported boundary and open research

Primary embedding support is finite affine Boolean inference under declared
family/source assumptions, widths 2–8 for independently validated learning,
and exact conditional prediction. Width-one learning returns `Uncertain` because
identification leaves no distinct held-out input. Existing lower-level reference
APIs retain their prior bounds. Incoming artifacts are inert data and cannot
authorize execution or independent trust.

Local exchange uses two actual caller-owned engine handles and explicit grants.
It is not a new arbitrary-remote adapter or proof that an external API is honest.
The existing TLS configured service remains a separate documented interface.
Native callbacks cannot be forcibly preempted in-process. Supported local-file
recovery is not a power-loss or network-filesystem guarantee.

One-host software qualification, independent two-host deployment, scientific
advantage and public delivery are separate outcomes. Two-host validation remains
**OPEN_UNAVAILABLE**, as requested by the owner. Power-loss durability and general
transfer efficiency remain unqualified. The next research workload should test a
costly search result with cheaper independent certification under a new prospective
protocol; the current structural learner can retain the same model in isolation,
so repetition alone cannot establish an exchange advantage.
